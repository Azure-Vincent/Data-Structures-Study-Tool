# DS Study Lab 2.0.0 — Learning modules and a professional academic structure

DS Study Lab is now organized as an independent data structures and algorithms platform: seven learning modules, a navigation built around the kind of work you are doing, one consistent set of names and pseudocode conventions in every language, and three new sections. Everything that worked in 1.2 still works, and **your saved progress carries over automatically**.

## Highlights

- **Seven learning modules** replace the eight numbered lessons.
- **Three new sections:** Learning Modules (overview), C++ Implementation (all 34 complete programs) and Knowledge Assessment (module and comprehensive assessments).
- **Content rewritten as an independent reference:** no references to any course's lecture notes, slides or page numbers remain.
- **One naming and pseudocode convention** across C++, Python and pseudocode (`head`, `prev`/`next`, `front`/`rear`, `create_node()`, explicit `end if` / `end while`, four-space indentation).
- **Automatic migration** of completed steps, practice sessions, review schedules and saved pseudocode.

Long modules are divided into **parts** (for example *Nodes, creation and insertion · Deletion and traversal · Circular singly linked lists*), shown as headings in the module outline. Every step is labeled with the kind of work it asks for: *Conceptual Foundations, Data Structure Representation, Memory Visualization, Algorithm Execution, Algorithm Tracing, Pseudocode Interpretation, Pseudocode Construction, C++ Implementation, Error Identification and Debugging* or *Application and Problem Solving*. Callouts are labeled *Technical Note, Terminology, Prerequisite, Extension* or *Common Errors and Edge Cases*.

Every module still ends with the progression **predict the output → complete the code → write the pseudocode**, now using only that module's own programs. The Queue module gains its own introduction and terminology note, and the stack, queue, tree and graph modules each have their own "common errors and edge cases" note and exercises (237 steps in total, up from 228).

## New and renamed sections

- **Learning Modules** — an overview of the seven modules with summaries, parts, progress and a *Begin / Continue / Review* button for each.
- **C++ Implementation** — all 34 complete programs grouped by module. Each runs step by step on the diagram, with the matching C++, Python or pseudocode statement highlighted and the variables and call stack shown.
- **Knowledge Assessment** — an 8-exercise assessment for each module and a 14-exercise comprehensive assessment across all modules. Assessments use the lowest level of guidance (no worked steps) and do not insert follow-up exercises after an incorrect answer. The latest and best result of each assessment is recorded and shown in Learning Progress. Each answer also counts toward concept mastery.
- **Cumulative Review** (formerly Pseudocode drills) — the same spaced-review schedule, with neutral grades: *recalled*, *recalled with difficulty*, *not recalled*. Topics are now the seven modules. The due badge sits under Pseudocode Development in the sidebar.

## Content and conventions

**Independent content.** References to lecture notes, slides, handwriting and page numbers are gone. Where the old material corrected the notes, the content is now a neutral **Technical Note** that describes the common error and the correct version (for example *“Single-node list: an incomplete delete_at_end leaves head dangling”*). Material beyond the core curriculum is labeled **Extension**.

**Standard identifiers**, identical in C++, Python and pseudocode:

| Before | Now |
|---|---|
| `start` | `head` |
| `getnode()`, `creatlist()` | `create_node()`, `create_list()` |
| `newnode`, `nodectr`, `ctr` | `new_node`, `node_count`, `i` |
| `countnode()` | `count_nodes()` |
| `insert_at_beg`, `insert_at_mid` | `insert_at_beginning`, `insert_at_position` |
| `delete_at_beg`, `delete_at_last`, `delete_at_mid` | `delete_at_beginning`, `delete_at_end`, `delete_at_position` |
| `left` / `right` (doubly linked lists) | `prev` / `next` (trees keep `left` / `right`) |
| `F` / `R` (array queues) | `front` / `rear` |
| `InsertQ` / `DeletQ` | `enqueue` / `dequeue` |

**Standard definitions.** Depth counts edges (the root has depth 0, depth = level). Binary tree shapes use the textbook names *full* (strictly binary), *perfect* and *complete*. The two array-stack conventions are named the *count convention* (top = number of items) and the *index convention* (top = index of the top item). Example graphs and trees are named by their shape (for example *Undirected graph (a–i)*, *Example tree A–G*).

**One pseudocode convention**, explained in Module 1 (*Code conventions*) and in `docs/PSEUDOCODE.md`:
- `=` assigns and `==` compares;
- `NULL` means “no node” (it corresponds to `nullptr` in C++ and `None` in Python);
- every block closes explicitly: `end if`, `end while`, `end for`, `end function`;
- four-space indentation; loops that test after the body use `do … while`;
- functions declare their parameters and return values with `return`.

The Pseudocode Development editor now indents by four spaces (Tab, Shift+Tab, Enter and *Tidy indentation*), and syntax errors suggest the matching closing word (for example “Close it with a line *end if*”).

**Interface wording.** Feedback reads *Correct.* / *Incorrect.*; exercise types have descriptive names (*Prediction, Pointer Manipulation, Code Completion, Error Identification, Pseudocode Writing*, …); empty states, tooltips and error messages were rewritten in a consistent, professional tone with American spelling. The C language tab is labeled *C*.

## Your progress

Progress saved by 1.x is upgraded the first time 2.0 starts (exported progress files are upgraded when imported):

- **Completed steps** keep their identity and are counted in the module that now contains them. Because some modules gained new steps, a lesson you had finished may show its module as almost complete.
- **Practice sessions** in progress continue; a lesson practice session becomes a module practice session. Attempts and error history are kept.
- **Cumulative Review schedules** are unchanged; review topics are mapped to modules (*Linked lists* → Singly and Doubly Linked Lists, *Stacks & queues* → Stack and Queue Data Structures, *Arrays* → Memory Management and Pointer Fundamentals).
- **Saved pseudocode** for list exercises is updated from `start` to `head`. In doubly linked lists, `left` and `right` are still accepted as other names for `prev` and `next`.
- **Old links and bookmarks** (`#/lesson/…`, `#/drills`, `#/explore/code`) open the corresponding step or page.
